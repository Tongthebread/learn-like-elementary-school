# Exam Preparation Mode

Read this reference when the learner asks to prepare for a quiz, test, midterm, final, certification, or other examination.

## Establish the exam target

Use available course materials to infer the scope. If the learner has a syllabus, learning objectives, past exam, formula sheet, grading rubric, or exam date, invite them to provide it. Do not stop when those items are unavailable; state the inferred scope and begin.

Never promise a grade or guarantee that every possible exam question is covered.

## Build a coverage map

Create a compact table with one row per major topic:

| Topic | Must know | Must be able to do | Common traps | Evidence of mastery | Status |
|---|---|---|---|---|---|

Use these statuses:

- **Not checked** — no performance evidence yet.
- **Developing** — succeeds with substantial hints or has inconsistent reasoning.
- **Secure** — solves representative standard questions independently and explains why.
- **Exam-ready** — also handles mixed, unfamiliar, or time-constrained questions reliably.

Do not mark a topic secure based only on self-report or reading the explanation.

## Run the preparation cycle

### 1. Diagnostic

Sample every major topic with a manageable number of questions. Include at least one explanation or reasoning prompt so guessing is visible. Do not teach answers before the learner attempts them.

### 2. Focused repair

For each weakness:

1. Identify the first missing concept or reasoning step.
2. Reteach it at the appropriate depth.
3. Work one example together.
4. Give a close transfer problem.
5. Give a less familiar problem after the close transfer succeeds.

### 3. Mixed retrieval

Mix topics and remove labels that reveal which method to use. Include older material alongside newly studied material. Ask the learner to justify method selection before calculating or writing a final answer.

### 4. Mock exam

Create a realistic exam only after enough topics have been taught or diagnosed. Match any known format, duration, permitted aids, topic weighting, and difficulty. Otherwise, state reasonable assumptions.

Provide:

- instructions and time budget;
- point values;
- a balanced set of questions;
- a separate answer key and grading rubric; and
- no inline hints unless the learner requests an assisted mock.

### 5. Grade and remediate

Score both answers and reasoning. For every lost point, classify the cause:

- missing knowledge;
- concept confusion;
- wrong method selection;
- execution or calculation error;
- incomplete justification;
- misreading the question; or
- time-management problem.

Summarize patterns rather than only listing wrong answers. Create a short retry set using new problems that target the same underlying weaknesses.

## Maintain an error log

Keep a concise table during the conversation:

| Topic | Error pattern | Correct idea | Next check |
|---|---|---|---|

Recheck a weakness later with a new question. Do not treat a correction copied immediately after feedback as strong evidence of retention.

## Readiness report

When asked whether the learner is ready, report:

- secure topics;
- weak or untested topics;
- performance under mixed or timed conditions;
- recurring error patterns;
- the highest-value next study actions; and
- the evidence supporting the assessment.

Use calibrated language such as “strong on standard mutex questions but not yet tested on mixed synchronization design.” Avoid unsupported percentages or guarantees.
